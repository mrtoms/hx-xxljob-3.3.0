1升级概述与兼容性结论

从 2.3.0 直接升级到 3.3.0 属于跨大版本迁移，不能无缝升级。核心差异如下：

变更点2.3.x3.3.0影响
JDKJDK 8 起步JDK 17+服务器、执行器都要换 JDK 17
Spring Boot2.x（javax.*）3.x（jakarta.*）自定义代码里 javax.servlet 等包需改为 jakarta.*
数据库结构旧 tables.sqlxxl_job_user 表结构变更需 ALTER 或重建，详见第 2 节
密码哈希MD5（32 位）SHA-256（64 位）旧密码无法登录，需重置
admin↔executor 协议旧协议（ReturnT）新协议（Response + 强制 token 头）执行器必须同步升级到 3.3.0
⚠ 关键结论：2.3.0 的 admin 与执行器都要一起升到 3.3.0；数据库 xxl_job_user 表要加 token 列并改密码哈希。官方文档中"2.4.* 可无缝升级"仅指 2.x 线内部，不适用于 2.3 → 3.x。
关于 CVE：本次升级修复的 CVE-2022-36157、CVE-2022-43183 在 2.3.1 即已修复；若只为修 CVE，升级到 2.x 线最后一个版本 2.4.2 也可。本指南按升级到 3.3.0 编写。

2数据库迁移

3.3.0 只有 xxl_job_user 这一张表有变化（其余 job_info / log / registry / lock 等兼容）：

差异点2.3 老表3.3.0 新表
token 列无varchar(100) DEFAULT NULL（登录 token）
password 长度varchar(50)varchar(100)
密码哈希算法MD5SHA-256

2.1 老库增量 ALTER（保留数据，推荐）

-- 1) 新增 token 列
ALTER TABLE `xxl_job_user`
  ADD COLUMN `token` varchar(100) DEFAULT NULL COMMENT '登录token' AFTER `password`;

-- 2) 加宽 password（SHA-256 是 64 位）
ALTER TABLE `xxl_job_user`
  MODIFY COLUMN `password` varchar(100) NOT NULL COMMENT '密码加密信息';

-- 3) 重置 admin 密码为 123456（3.x 用 SHA-256 存储）
UPDATE `xxl_job_user`
SET `password` = '8d969eef6ecad3c29a3a629280e686cf0c3f5d5a86aff3ca12020c923adc6c92'
WHERE `username` = 'admin';

8d969eef...c6c92 即 SHA-256("123456")，与 3.3.0 脚本里默认 admin 密码一致。

2.2 备份与回滚

-- 升级前备份（保存原始 MD5 密码）
CREATE TABLE xxl_job_user_bak_23 AS SELECT * FROM xxl_job_user;

-- 需要回滚 2.3 时：恢复密码为原 MD5 值（token 列可留可删，2.3 不理会）
UPDATE xxl_job_user u
JOIN xxl_job_user_bak_23 b ON u.id = b.id
SET u.password = b.password;
⚠ 回滚提示：改完 SHA-256 后，老 2.3 无法用同一套密码登录（2.3 用 MD5 比对）。所以 2.3 和 3.3 不要同时指向同一个库的同一批账号。

2.3 全新部署建库脚本

CREATE database if NOT EXISTS `xxl_job` default character set utf8mb4 collate utf8mb4_unicode_ci;
use `xxl_job`;
-- ... 粘贴 3.3.0 的 tables_xxl_job.sql 全部内容（已含 token 列 / SHA-256 密码）...
库名可自定义：若用 yuncheng_xxljob 等自定义库名，只需保证「JDBC URL 里的库名 = 建表脚本 use 的库名 = 实际存在的库」三者一致。mysql 镜像 MYSQL_DATABASE 默认只建 yuncheng_nacos，xxl_job 库要靠 mysql/init/ 初始化脚本建。

3代码升级（admin + 执行器）

3.1 版本号统一到 3.3.0

<xxl-job.version>3.3.0</xxl-job.version>

好消息：XxlJobSpringExecutor（com.xxl.job.core.executor.impl.XxlJobSpringExecutor）和 @XxlJob（com.xxl.job.core.handler.annotation.XxlJob）包路径在 3.3.0 未变，代码几乎不用改。

3.2 执行器配置类补 accessToken（关键）

升级后必须给执行器设置 accessToken，否则注册会被 3.3.0 admin 拒绝（见 6.4）：

@Value("${xxl.job.accessToken}")
private String accessToken;

@Bean
public XxlJobSpringExecutor xxlJobExecutor() {
    XxlJobSpringExecutor xxlJobSpringExecutor = new XxlJobSpringExecutor();
    xxlJobSpringExecutor.setAdminAddresses(adminAddresses);
    xxlJobSpringExecutor.setAccessToken(accessToken);   // ← 新增
    xxlJobSpringExecutor.setAppname(appname);
    xxlJobSpringExecutor.setPort(port);
    xxlJobSpringExecutor.setLogRetentionDays(logRetentionDays);
    return xxlJobSpringExecutor;
}

3.3 执行器 Nacos 配置补 accessToken

xxl:
  job:
    admin:
      addresses: http://192.168.1.244:8080/xxl-job-admin
    accessToken: default_token      # ← 新增，与 admin 一致
    executor:
      appname: xxl-job-executor-sample
      port: 9999
      logretentiondays: 3
⚠ 一致性：admin 与所有执行器的 accessToken 必须一致；不改默认就是 default_token（能跑但不安全，建议换成随机长 token）。

4Docker 部署配置

4.1 docker-compose（xxljob 服务）

  # ========== XXL-Job ==========
  xxljob:
    image: eclipse-temurin:17-jre        # 3.3.0 需要 JDK17
    container_name: xxljob
    restart: unless-stopped
    networks:
      - esafe-net
    ports:
      - "${XXL_JOB_PORT:-8080}:8080"
    env_file:
      - .env
    environment:
      TZ: Asia/Shanghai
      JVM_OPTS: >
        ${JVM_COMMON_OPTS}
        ${JVM_COMMON_DSYSTEM}
        -Dspring.config.additional-location=file:/app/config/application.properties
      MYSQL_HOST: mysql
      MYSQL_PORT: 3306                   # 容器网络内固定 3306
      MYSQL_DB: ${XXL_JOB_MYSQL_DATABASE:-xxl_job}
      MYSQL_USER: ${XXL_JOB_MYSQL_USER:-root}
      MYSQL_PWD: ${XXL_JOB_MYSQL_PASSWORD:-${MYSQL_ROOT_PASSWORD}}
      XXL_JOB_LOG_RETENTION_DAYS: ${XXL_JOB_LOG_RETENTION_DAYS:-30}
    volumes:
      - ${ESAFE_HOME}/jar/xxl-job/xxl-job-admin-3.3.0.jar:/app/app.jar:ro
      - ${ESAFE_HOME}/jar/xxl-job/application.properties:/app/config/application.properties:ro
      - ${ESAFE_HOME}/logs/xxl-job:/data/applogs          # 应用日志
      - ${ESAFE_HOME}/logs/xxl-job/jvm:/data/logs/jvm     # JVM GC/错误日志
    command: ["sh", "-c", "exec java $${JVM_OPTS} -jar /app/app.jar"]
    depends_on:
      mysql:
        condition: service_healthy
⚠ 注意点：
  • 缩进必须与其它服务一致（xxljob: 缩进 2 格）。
  • 镜像必须是 JDK17；JVM_COMMON_OPTS_8 这类 Java8 参数不能用。
  • 配置加载用 -Dspring.config.additional-location=...，不要用 -Dxxl.job.config.location（无效参数）。
  • xxl-job-admin 不依赖 Redis，REDIS_* 和 depends_on: redis 可删。

4.3 .env 变量

### XXL-Job
XXL_JOB_PORT=8080
XXL_JOB_MYSQL_DATABASE=xxl_job
XXL_JOB_MYSQL_USER=root
XXL_JOB_MYSQL_PASSWORD=xxxxxx
XXL_JOB_LOG_RETENTION_DAYS=30            # 必须 >=3，否则关闭日志清理
XXL_JOB_ACCESS_TOKEN=替换成随机token      # 可选，但强烈建议，勿用 default_token
env 注入机制：服务有 env_file: .env 时，.env 里所有变量会整体注入容器，无需在 environment: 里逐条列出。外部 application.properties 用 ${VAR:default} 显式占位符即可解析。

5部署验证清单

  • 数据库 xxl_job_user 已加 token 列、password 加宽、admin 密码改为 SHA-256。
  • admin 与所有执行器版本统一为 3.3.0，运行环境 JDK 17。
  • 执行器代码已 setAccessToken(...)，Nacos 配置已加 xxl.job.accessToken（与 admin 一致）。
  • compose 缩进正确、镜像为 eclipse-temurin:17-jre、用 spring.config.additional-location 加载外部配置。
  • 启动日志出现 HikariCP - Start completed + Tomcat started on port 8080。
  • admin 控制台用 admin/123456 登录成功，并立即改强密码。
  • 「执行器管理」中执行器显示在线，无 MissingRequestHeaderException 告警。
  • 触发一次任务，执行器正常执行并回调结果。

6常见问题排查

6.1 Maven 构建报 GPG 签名错误

Could not determine gpg version

xxl-job 的 pom 配了 maven-gpg-plugin 用于发布签名，本地构建不需要：

mvn clean install -Dgpg.skip=true -Dmaven.javadoc.skip=true -DskipTests

IDEA 里加到 Run Configuration 的 Command line 框；或直接在根 pom 的 <properties> 加 <gpg.skip>true</gpg.skip>。

6.2 登录报 Unknown column 't.token'

Unknown column 't.token' in 'field list' ... FROM xxl_job_user

说明数据库还是 2.3 老结构，缺 token 列。执行第 2.1 节的 ALTER + 重置密码即可。

6.3 执行器触发报 Connect timed out（172.18.0.16:9999）

trigger error, please check if the executor[http://172.18.0.16:9999/] is running

这是执行器用 Docker 内网 IP 注册、调度中心（宿主机/IDEA）无法路由导致的网络问题。修复：执行器用宿主机可达 IP 注册（xxl.job.executor.ip 或 xxl.job.executor.address 显式指定），并映射 9999 端口；或 admin 与执行器放同一 Docker 网络。

6.4 一直刷 MissingRequestHeaderException

Required request header 'XXL-JOB-ACCESS-TOKEN' ... is not present

3.3.0 admin 的 /api/registry、/api/callback 强制要求 XXL-JOB-ACCESS-TOKEN 请求头；执行器没配 accessToken 导致注册被拒。修复见第 3.2、3.3 节：执行器补 accessToken，与 admin 一致。

6.5 logretentiondays 设了但"不生效"

官方限制：xxl.job.logretentiondays ≥ 3 才生效；小于 3 时代码返回 -1（关闭日志清理），日志反而越积越多。另外该值指调度中心 xxl_job_log 表的清理天数（执行器本地日志文件是 xxl.job.executor.logretentiondays，同样最小 3 天）。
